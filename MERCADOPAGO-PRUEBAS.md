# Mercado Pago Checkout Pro: pruebas

Este flujo crea órdenes de prueba mediante Orders API y cobra únicamente la tarifa del 5 %. No implementa cobros reales. Los estados de pago de prueba son independientes de la confirmación de la reserva.

1. La tabla ya se creó en la base local configurada durante la implementación. En otra base existente, respaldarla y aplicar `backend/prisma/mercadopago_test.sql` una sola vez, solo si la tabla no existe. Generar el cliente con `npm run generate`. La tabla es necesaria también para el listado de reservas en administración.
2. En la aplicación de Mercado Pago, seleccionar **Prueba** en Credenciales. Obtener el Access Token y el ID numérico del vendedor de prueba de esa misma aplicación. No usar credenciales productivas: Mercado Pago usa el prefijo `APP_USR` tanto en prueba como en producción.
3. Configurar el webhook de prueba para el evento de órdenes en una URL HTTPS pública que apunte a `/api/v1/mercadopago-test/webhook`; obtener la firma secreta del panel. No publicar el secreto ni el Access Token.
4. En el entorno privado del backend, establecer `MERCADOPAGO_TEST_ACCESS_TOKEN`, `MERCADOPAGO_TEST_SELLER_ID` y `MERCADOPAGO_TEST_WEBHOOK_SECRET`. Desactivar Izipay, Culqi y la simulación, y establecer `MERCADOPAGO_TEST_ENABLED=true` solo después de verificar que se usan los datos de prueba.
5. Desplegar frontend y backend, crear una reserva y completar el pago usando las instrucciones y datos de prueba oficiales. Verificar orden aprobada y rechazada, notificaciones firmadas, duplicados, reembolsos, reintentos y consulta desde administración. El backend contrasta el vendedor y rechaza órdenes cuyo ID no tenga el prefijo de prueba `ORDTST`.

No se ha probado contra la cuenta real de Mercado Pago. Si falla la creación de una orden, la solicitud permanece pendiente y se requiere atención administrativa; no se debe intentar repetidamente sin revisarla. Si se cierra la pantalla de confirmación, el cliente no tiene aún un mecanismo para recuperar el enlace: administración puede consultar el estado. Antes de cobrar dinero real hacen falta implementación independiente de producción, evaluación del modelo de negocio, pruebas completas y políticas de cancelación y reembolso.
